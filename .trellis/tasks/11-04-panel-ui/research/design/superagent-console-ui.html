Superagent Console UI

Static, self-contained specimen document for the operator console of dsh-superagent (DeepSeek Harness). It answers three questions in this order: is it healthy, what is it doing, what needs me. Work waiting on a person comes first; a healthy state takes almost no space.

Everything inside a framed app view is simulated product UI; the grey annotation boxes beside each frame are design notes for Part B and are not product copy. Controls inside the frames are inert illustrations: buttons do nothing, link-outs do not navigate, dialogs and sheets are drawings, not live modals. Index links, native disclosures and the theme preview toggle above work without JavaScript (the toggle uses CSS :has()).

SHELL

Shared application shell

DOCUMENT

Every desktop frame below uses the same shell: a 216 px sidebar (Overview, Tickets, Threads, Decisions, Sources, System), a 48 px top bar, and a content region. The frames are 1140 px wide design artboards; scroll a frame horizontally if this window is narrower.

Shell rules carried by every specimen

  • Sidebar badges appear only for evidenced work waiting on a person: the total of GET tickets?state=person (fallback: overview.person.length while the list has not loaded). A zero badge is omitted. List-filter tabs keep their counts regardless.
  • Top bar: API connection indicator (reachability of /orchestrator/api/ plus the time of the last successful fetch), Executor pause switch (state.paused; a change opens a confirmation first), search trigger with the visible shortcut (⌘K on macOS, Ctrl K elsewhere; the button is always visible), and the theme control (Part B: next-themes, attribute="class", system default, menu with System / Light / Dark). Connection status, Source health and Executor state are three separate facts and are never merged.
  • Skip link: the first focusable element in the app is “Skip to content”, visually hidden until focused (drawn visible in specimen 5). Landmarks: nav “Console navigation”, main, page h1. In this document the app page titles are rendered as h3 to keep the catalogue outline valid; Part B uses h1.
  • Focus: 2 px ring in --ring with 2 px offset on every interactive element; never clipped by overflow containers (tables use padding so the ring stays visible).
  • At 390 px the sidebar becomes a sheet behind a menu button (specimen 14): opening moves focus to the sheet’s close button, Tab is contained in the sheet, Escape or the scrim closes it and focus returns to the menu button.
  • Timestamps: absolute UTC first (YYYY-MM-DD hh:mm:ss UTC, machine value in datetime), relative text second and muted. Relative text is recomputed on a 30 s timer without live-region announcements; only action outcomes are announced (polite region for success, assertive for errors).

Contract gaps, conflicts and departures from the brief

  • Asker (Tickets list) and Actor (Decisions): TicketListView items and DecisionView carry no actor; both columns show “—” with a screen-reader note. Recommendation for Part B: drop these columns unless src/app/api.ts supplies the field; do not substitute a Thread’s latest writer.
  • Requeue: every supplied Trigger has actions.requeue: false, so no enabled Requeue or its confirmation could be staged on a record; the control is drawn disabled with its reason and specified in the inventory.
  • Observe mode: the digest says observe records accepts as would-accept, but the SAMPLE has mode: observe together with seven explicit accept Decisions that created Tickets; only the inferred rule match is outcome: wouldAccept. The design renders each record’s own kind/outcome and the Overview text follows the brief’s wording. Part B should resolve against the source contract and src/app/settings.ts.
  • Host-text placeholders: no setup envelope example and no failed-stop response exist in the bundle; 3c and 13d draw marked placeholders instead of invented host messages. The Overview problem payload shapes for setup, no-source, no-allowed, executor-paused and runtime-error are not in the bundle; only the kind is rendered for them.
  • Specimen clock: fixtures.json has no capture time, so relative times in SAMPLE frames use 03:00:00 UTC (03:01:10 UTC for the problem variant), stated in each annotation and derived from the newest supplied timestamps. Snapshot relative times use the file’s approximate ≈01:40 UTC and are marked ≈.
  • Derived values: tab counts in 4 are derived from the complete SAMPLE list (total 7, next_offset null); “Worktree branch” is derived from the configured prepare command and labelled so; executor.idle is read as idle-stage Tickets (undefined in the digest); the Sources “last 24 h” label follows the fixture author’s note, not the digest.
  • Tab counts not shown on Threads (Subscribed/Evaluating/Recent) and Decisions (Work/Stop/Ignore/Unavailable): the bundle has no per-filter responses and the digest does not define their membership; only All carries a count.
  • Policy version mismatch in the capture: settings.policyVersion and history.policyVersion are b406b04a… while history.items[0].policyVersion (revision 5) is aa2775ff…; both are shown as recorded, neither is “corrected”.
  • Delivery to people: TicketPageView has no reply receipts, so no timeline item claims delivery to people; the legend chip exists for a future receipt field. Progress/ready/blocked reports are shown as worker → Router.
  • Heading levels: app page titles are h3 inside this catalogue so the document outline stays valid; Part B uses h1. Landmarks inside frames carry specimen-numbered labels to stay distinguishable in one document.
  • Extra token --destructive-foreground (not in the A5 list) is defined for the destructive button text in both themes; everything in the A5 list is present with the same names in both themes.
  • No product features or routes were added; writes are limited to the six permitted operations; settings and prompts are read-only with “Edit in DSH panel” link treatments; the DSH destination is http://127.0.0.1:3082/ with no deep-link template.
