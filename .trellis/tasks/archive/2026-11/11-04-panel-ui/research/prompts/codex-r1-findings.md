1. **[med] HTTP 500 can falsely report that a write was refused.** [client.ts:30](/home/gerald/workloads/dsh-superagent-prototype/panel/src/api/client.ts:30), [confirm-action.tsx:52](/home/gerald/workloads/dsh-superagent-prototype/panel/src/components/confirm-action.tsx:52). Only offline/malformed failures are “unconfirmed”; a JSON 500 displays “The host refused the action.” But pause commits settings before awaiting delivery ([settings.ts:206](/home/gerald/workloads/dsh-superagent-prototype/src/app/settings.ts:206)). A subsequent failure can therefore leave processing paused while the UI claims refusal. **Fix:** treat server failures after submission as outcome-unconfirmed, preserve the error detail, and reconcile through GETs. Reserve “refused” for explicit rejection responses.

2. **[med] A pagination cursor carries over into another Thread.** [thread.tsx:118](/home/gerald/workloads/dsh-superagent-prototype/panel/src/routes/thread.tsx:118). `before` lives in component state and is not reset when `$key` changes; the route has no remount dependency. Page backward in Thread A, then follow a correlated Thread B or select B through search: B is requested with A’s cursor. If B’s messages are newer, its timeline incorrectly says “No Triggers on this Thread.” **Fix:** key/remount the detail component by Thread key, or scope cursor state to that identity.

3. **[med] “Show more” cannot reach records beyond 1,000.** [tickets.tsx:25](/home/gerald/workloads/dsh-superagent-prototype/panel/src/routes/tickets.tsx:25), [threads.tsx:63](/home/gerald/workloads/dsh-superagent-prototype/panel/src/routes/threads.tsx:63). Both lists increase `limit` without sending `offset`; the host clamps the limit to 1,000 ([http.ts:140](/home/gerald/workloads/dsh-superagent-prototype/src/app/http.ts:140)). Above that population, subsequent clicks return the same first 1,000 records, retain the button, and create additional cache entries for duplicate payloads. **Fix:** consume `next_offset` with bounded pages and deduplication.

4. **[med] Overview silently hides or misrepresents Eval activity.** [overview.tsx:87](/home/gerald/workloads/dsh-superagent-prototype/panel/src/routes/overview.tsx:87). The component fetches five `evaluating` Threads but wraps only the Tickets query in `QueryView`. Thread failures therefore hide activity or leave stale Evals displayed without a stale marker. Additionally, the API’s `evaluating` filter includes queued Threads, while rendering requires `thread.evaluating`: five newer queued Threads can occupy the entire result and hide running Evals. **Fix:** handle the Thread query’s loading/error/stale states independently, render queued entries, and disclose truncation with a link to the full filtered list.

5. **[med] An unavailable settings response becomes a fabricated default-model claim.** [ticket.tsx:183](/home/gerald/workloads/dsh-superagent-prototype/panel/src/routes/ticket.tsx:183), [ticket.tsx:209](/home/gerald/workloads/dsh-superagent-prototype/panel/src/routes/ticket.tsx:209). Missing `settings.data` takes the same branch as a confirmed null model and displays “DSH default.” A Ticket can load while settings fail, so this asserts a configuration value that was never received. Failed refreshes also retain the previous model without identifying it as stale. **Fix:** apply the settings query’s loading/error/stale handling to this card; show “DSH default” only after a successful response establishes it.

6. **[med] Confirmation dialogs can place their actions outside the viewport.** [alert-dialog.tsx:55](/home/gerald/workloads/dsh-superagent-prototype/panel/src/components/ui/alert-dialog.tsx:55), [confirm-action.tsx:71](/home/gerald/workloads/dsh-superagent-prototype/panel/src/components/confirm-action.tsx:71). The popup is fixed and vertically centred, with neither a viewport height limit nor vertical scrolling. It renders record titles/previews and host errors without a height bound. Long content at mobile width or enlarged text can push Cancel/Confirm below the viewport; scrolling the page cannot expose the bottom of the fixed popup. **Fix:** constrain the popup to the available viewport height and make its content scrollable while keeping actions reachable.
