## Product and purpose

dsh-superagent is a proactive agent bundle for DeepSeek Harness (DSH). It listens to one GitHub repository and optionally to Feishu (飞书) group chats, evaluates incoming messages under a Policy, turns authorised requests into Tickets, and runs each Ticket in its own worker Session. The main Session is the Router; worker Sessions execute.

The operator is a system architect who needs to answer:
1. Is it healthy?
2. What is it doing?
3. What needs me?

Prioritise work waiting on a person, then current activity, then supporting detail. Keep healthy and empty states calm. The product principle supplied in this brief is: "a panel that shows only what needs a person. It lists first what waits for a person. A healthy state takes no space." Its cited source is docs/000-philosophy.md:21; do not claim to have checked that file unless you read it.

## Domain vocabulary

Keep these names and meanings:
- Source: a channel the agent listens to, such as GitHub or Feishu. States: missing, off, error, setup, starting, paused, ready. A Source also has health parts.
- Trigger: one incoming item, such as an Issue comment or chat message.
- Thread: the conversation containing a Trigger, such as an Issue, PR or chat topic.
- Decision: the Eval verdict on a Trigger: accept, reopen, stop, ignore, unavailable. In observe mode, evaluated requests are not acted on automatically; an observed accept is presented as "Would accept", according to the contract. Do not relabel every Decision as "Would accept". Observe mode alone does not determine eligibility for the permitted manual writes.
- Ticket: authorised work. Stages: person, working, idle, ended. person means waiting on a person, with reasons such as delivery, answer, review, blocked or failed; its filter label is "Pending". working includes running or queued work as the contract specifies. idle means waiting for a Trigger.
- Assignment / Mandate: who asked, under which Policy rule, and what was authorised.
- Policy: who may originate work through each Source, including allow-lists and rules.
- Executor: the worker pool, including running, queued and maximum workers. Pause suspends new evaluations, worker dispatch and channel delivery while Sources continue recording Triggers; it does not terminate running Workers.

Keep enum values, display labels and action eligibility distinct. Do not invent additional domain states.

## Runtime boundaries

The shipped console reads operational data only from the local management API: plain HTTP JSON under /orchestrator/api/*, using polling rather than WebSocket. The supplied architecture is loopback-only and has no authentication.

Workers run with full access as the operator's OS user. UI confirmations and controls are conveniences, not a security boundary, as stated by architecture ADR-23. Neither the request header nor the Origin guard establishes operator authentication or worker isolation.

Settings and prompts remain read-only in this console, with editing in the DSH panel. Worker Sessions open through links to the DSH web UI. Keep the specified screens, paths, routes and write whitelist; add no product features or API routes.

## Visual and accessibility quality

Use a calm, coherent shadcn/ui-style interface: neutral surfaces, one accent, restrained status colour, clear hierarchy, useful whitespace, compact tables and tabular numerals. Prefer familiar controls and specific labels over decorative dashboard furniture.

Provide light and dark themes through the same semantic token names. Respect the installed Tailwind 4 and shadcn/Base UI conventions in Part B; do not substitute another primitive library or upgrade packages merely for appearance.

Target WCAG 2.2 AA:
- Maintain at least 4.5:1 contrast for interface text, as this brief requires, and at least 3:1 for essential non-text control and state indicators against adjacent colours.
- Use semantic headings, landmarks, labels, buttons, links and tables; include a skip link and accessible names for icon-only controls.
- Support keyboard operation, logical focus order and visible focus that remains unobscured.
- For implemented modal search, dialogs and sheets: provide appropriate initial focus, contained Tab navigation, Escape dismissal and focus return. Prefer the safe choice for a difficult-to-reverse confirmation.
- Convey status with text or a meaningful icon as well as colour. Essential information must not depend on hover.
- Keep targets at least 24 × 24 CSS pixels or satisfy the applicable WCAG spacing exception.
- At 390 px, retain information and actions without page-level horizontal scrolling. Confine wide tables to labelled, keyboard-usable scrolling containers; wrap long IDs, paths and messages.
- Check zoom and reflow as part of accessibility verification; 390 px specimens alone do not prove AA conformance.
- Announce meaningful action outcomes without repeatedly announcing every poll or relative-time update.

Use English interface copy. For API text supplied as {zh, en}, use en. Preserve original record content, including Chinese names and chat text; do not invent translations.
